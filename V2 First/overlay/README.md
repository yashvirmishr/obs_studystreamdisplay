# Study Stream 2.0 — OBS Overlay Renderer (`overlay/`)

Standalone React + Vite + TypeScript renderer loaded by OBS **Browser
Sources**. Zero Tauri dependencies (architecture invariant 3). Backend binds
`127.0.0.1:47831` only (invariant 1).

## How OBS consumes this

1. Run the overlay dev server (`npm run dev`, port **5174**, strictPort) or
   serve the built output (`npm run build` + any static host / `npm run preview`).
2. In OBS, add one **Browser Source per OBS scene**, pointing at:

   ```
   http://127.0.0.1:5174/overlay/<scene_id>?token=<per-launch-token>
   ```

   - `<scene_id>` — identifies which overlay scene layout to render.
     Defaults to `study` when absent (real scene resolution arrives in Phase 3).
   - `?token=` — per-launch token generated by the Tauri shell; forwarded as
     the `token` query parameter on the WebSocket URL. The exact auth
     parameter name is pending confirmation (see below).
3. **Width/Height** should match your stream canvas (e.g. 1920×1080).
   Leave "Custom CSS" untouched — the page already sets a transparent body.
4. The renderer connects to `ws://127.0.0.1:47831/ws/overlay/{scene_id}` and
   auto-reconnects forever with exponential backoff (500 ms base, doubling,
   10 s cap, jitter) if the backend is down. While disconnected, a small
   corner banner ("backend unreachable — retrying") is shown; it never covers
   the full overlay.

## Transparency contract

`index.html`, `#root` and the stage element have no opaque background at any
level. OBS composites this page over the stream capture, so anything opaque
here would appear in the stream. Do not add backgrounds to `html`/`body`.

## Explicitly NOT done yet

- **Scene resolution** — `/overlay/<scene_id>` currently accepts any id
  (default `study`); there is no backend lookup of real scene definitions.
  Phase 3 (Overlay Studio) resolves which scene a URL maps to.
- **Widget rendering** — the stage is a placeholder. No widgets, no
  normalised-coordinate layout engine (positions will be 0..1 floats per
  architecture invariant 5).
- **Auth endpoint confirmation** — the `?token=` → WS query param mapping is
  an assumption documented in `src/connection/useOverlaySocket.ts`; the
  backend's actual `/ws/overlay` auth check is concurrent work and the param
  name may change.
- **Message protocol** — `onmessage` is deliberately a no-op; the event
  envelope (invariant 6) is wired up in later phases.

## Build

```bash
cd overlay
npm install
npm run build   # tsc (strict) + vite build
```
